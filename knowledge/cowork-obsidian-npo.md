# NPOのナレッジをコモンズにする：Obsidian × Claude Coworkで「正本一本化」を実現した話

> 横浜コミュニティデザイン・ラボ｜2026年6月
> 著：杉浦裕樹（代表理事）

---

## TL;DR

- NPO法人のナレッジは「誰かのメモリ」と「ツールの流行り廃り」に依存しがちで、蓄積するほど散逸する
- ObsidianのVaultを**唯一の正本**として、Claude Coworkにそこを操作させることで「正本一本化」を実現
- 数日の試行で、22年分の組織知を引き出せる状態の土台ができた
- このやり方と設計思想をコモンズとして公開する

---

## 背景：なぜNPOのナレッジは散逸するのか

横浜コミュニティデザイン・ラボは2003年設立。ヨコハマ経済新聞、LOCAL GOOD YOKOHAMA、さくらWORKS＜関内＞、FabLab Kannaiなど、22年間で多くのプロジェクトを手がけてきた。

その間、ナレッジ管理の主戦場は変遷し続けた。

```
メーリングリスト → Wiki → Google ドライブ → Notion → Claude.ai プロジェクト → …
```

どのツールも「今は便利」だが、数年後には「移行コストがかかる別の孤島」になっていた。特にAI活用が始まってからは、チャット履歴・AIのメモリ・Notionノート・Driveファイルが**三重・四重管理**になり、どれが最新で正しいかわからない状態が常態化していた。

### NPO固有の問題

- **スタッフの入れ替わり**：引き継ぎは口頭が多く、文書化が追いつかない
- **総会・理事会の繰り返し**：毎年似た書類を作り直す非効率
- **固有名詞・事実の揺らぎ**：「設立2001年」「設立2003年」どちらが正しい？（正解：2003年11月13日）

---

## 解決策：Obsidian Vault を「唯一の正本」にする

### 考え方

```
Obsidian Vault（正本）
    ↕ 読み書き
Claude Cowork（操作エージェント）
    ↓ 生成
outputs/（成果物：議案書・記事・申請書など）
```

**1トピック = 1正本ファイル**という原則を徹底する。

- 事実（年月日・固有名詞・数値）は `90_facts_register.md` に一元化
- 法人基礎は `01_org_basic.md`
- 運用ルールは `99_meta_rules.md`
- 成果物（docx・配布資料）は `outputs/` に分離して正本と混在させない

Vaultが正本であることをClaudeに明示し、Claudeはそこを読んでから動く。

### なぜObsidianか

| 理由 | 内容 |
|---|---|
| ファイルがすべてMarkdown | プレーンテキストなので将来のツール変更に強い |
| ローカルに保存 | クラウドサービスの終了・ポリシー変更リスクがない |
| コモンズ化しやすい | .mdファイルをそのままGitHubにpushできる |
| Coworkが直接読み書きできる | ツール間のコピペが不要 |

## 実装：ファイル構成と役割

```
横浜CDラボ/（Obsidian Vault内のプロジェクトフォルダ）
├── cowork_rules.md        # Coworkへの行動規範（最初に読む）
├── 99_meta_rules.md       # タグ・固有名詞・命名規約（運用ルール）
├── 00_INDEX.md            # 全体像・正本マップ・読み順
├── 90_facts_register.md   # 確定事実台帳（表記の唯一の正本）
├── 01_org_basic.md        # 法人基礎・役員・直近日程
├── 10_bylaws_regulations.md  # 定款・規程
└── outputs/               # 成果物（正本とは分離）
    ├── github-pages/      # このリポジトリのソース
    └── 議案書・議事録/
```

### cowork_rules.md の役割

これが最重要ファイル。Claudeがラボ関連の作業を始めるとき、**必ずこれを最初に読む**よう指示している。内容は：

- 正本の所在（VaultのどこにあるかをClaudeに明示）
- 無断での上書き・削除を禁止するルール
- 「止まる」ポイント（外部送信・削除の前に確認を求める）
- 出力の作法（敬語・構造化・次の一手を出す）

### 90_facts_register.md の役割

事実の揺らぎを防ぐための台帳。例：

- 設立日：**2003年11月13日**（「2001年」は誤り。法人番号0200-05-004834で確認済）
- 固有名詞：「ヨコハマ経済新聞」（「横浜経済新聞」は誤り）
- 総会の回次と年度の対応（取り違えが多発していたため）

毎回AIに推測させるのではなく、**確定事実はここに一元化して参照させる**。

## 数日やってみて起きたこと

### よかったこと

1. **同じ質問を毎回しなくなった**：「ラボの設立年は？」「総会の日程は？」をVaultが答える
2. **成果物の品質が上がった**：事実の誤りが減り、修正ラウンドが減った
3. **「次の一手」が出てくる**：現状把握と課題が構造化されているから、アクションに変換しやすい
4. **新しいメンバーへの引き継ぎ資料になる**：Vaultを見れば組織の全体像がわかる状態に近づいた

### 課題

- まだ未整備のファイルが多い（決算数値・役員名簿・過去議事録の正本化）
- Obsidianのスキルがない人は入り口が高い
- Claudeのコストが発生する（月額費用との費用対効果の検討が必要）

## 再現したい人へ：最小構成でのはじめ方

1. **Obsidian**をインストールしてVaultを作る（無料）
2. フォルダに `cowork_rules.md` を1ファイル作り、「このフォルダが正本」「ここを読んでから動く」とClaudeへの指示を書く
3. `90_facts_register.md` に組織の確定事実（設立年・正式名称・役員名）を書く
4. Claude Coworkを使い始め、作業のたびに正本ファイルを参照させる

**完璧なVaultを先に作る必要はない**。正本の「考え方」を持ちながら、作業のたびに少しずつ整備していくのが現実的。

---

## この取り組みをコモンズにしたい理由

「市民活動×テクノロジー×ローカル」は、まだ実践者が少ない領域だ。企業のノウハウは多いが、NPO・市民活動特有の制約（リソースの少なさ、スタッフの流動性、透明性の要請、ガバナンスの複雑さ）に対応した知恵はなかなか共有されない。

横浜CDラボがやってみたことを、そのままの形でここに置いておく。誰かの役に立てば、それがコモンズになる。
